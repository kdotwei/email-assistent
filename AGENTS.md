AI Agents and Models Collaborative Protocol (AGENTS.md)

> [System Directive - HIGH PRIORITY]
To all AI models, agents, and autonomous services (e.g., OpenCode, Codex, Cursor, Cline, etc.) operating in this workspace:
You MUST read and strictly adhere to the following context-retrieval and reporting protocols.

This document serves as the supreme guideline for all AI models and services operating within this project environment. To ensure development transparency, knowledge retention, and context continuity across multiple sessions and different AI agents, all AI entities MUST mandatorily retrieve context before tasks and generate/update work reports after tasks.

Project Development References

Before planning or implementing product features for this GenAI final project, agents MUST read the following project-specific references in addition to the reporting files under `reports/`:

• `docs/IDEAS_MEMO.md` - Original project idea and motivation.
• `docs/DEVELOPMENT_PLAN.md` - Recommended phased implementation roadmap, deliverables, and acceptance criteria.
• `docs/SOFTWARE_STACK.md` - Recommended software stack, architecture, project structure, provider design, and implementation order.

Agents SHOULD align new implementation work with these documents unless the human developer explicitly changes the direction. If implementation choices diverge from the documented plan or stack, record the reason in the corresponding report file.

Core Protocol 1: Context Retrieval (Read Before Acting)

Before initiating a new task, making architectural decisions, or attempting to fix a complex bug, the AI model/service SHOULD actively search for and read existing report-<service>-<model>.md files.

• Why? To thoroughly understand the historical context, previously attempted (and failed) methods, current blockers, and the overall progress of the project.

• Action: Look for reports generated by previous agents (or your past self) in the `reports/` directory to avoid redundant work and prevent repeating known mistakes.

Core Protocol 1.5: AI Transparency and Anonymity

All AI agents, models, and autonomous services MUST maintain complete anonymity in their work outputs.

**STRICTLY PROHIBITED:**

• **NO AI Identifiers**: Do NOT include any references to AI agents, model names, service names, or AI-generated markers in:
  - Code comments (inline or block comments)
  - Commit messages
  - Documentation
  - Log messages
  - Variable names or function names
  - File headers or metadata
  - TODO/FIXME notes
  - Any other user-facing or developer-facing content

• **Examples of FORBIDDEN content**:
  - `// Generated by AI`
  - `# Created by Claude/GPT/Gemini`
  - `[AI Agent: ...]`
  - `@ai-generated`
  - `// TODO: AI to fix this later`
  - Commit messages like "AI: updated config"
  - Using emojis in code, comments, commit messages, or documentation

**REQUIRED Behavior:**

• Write all code, comments, and documentation as if written by a human developer.
• Use professional, standard development practices without any AI attribution.
• Keep all work outputs indistinguishable from human-authored content.
• Do NOT use emojis in any work outputs (code, comments, commit messages, documentation, etc.).

**EXCEPTION:**

• AI identifiers ARE REQUIRED only in report files under `reports/report-<service>-<model>.md` as specified in Core Protocol 2.

Core Protocol 2: Mandatory Reporting (Write After Acting)

At the end of a conversation, upon task completion, or when a phase of work concludes, the AI model/service MUST summarize the work done, methods attempted, and issues encountered, and append this information into the corresponding report file.

1. Naming Convention

Report files must be created in the `reports/` directory (create this directory if it does not exist) and strictly follow this naming format:

Format: reports/report-<service>-<model>.md

• <service>: The tool or service executing the task (use lowercase, e.g., opencode, codex, cursor, cline).

• <model>: MUST use the exact official API model name (e.g., claude-3-5-sonnet-20241022, gpt-4o, gemini-2.5-pro).

Naming Examples:

• Using Claude 3.5 Sonnet via OpenCode: reports/report-opencode-claude-3-5-sonnet-20241022.md

• Using GPT-4o via Codex: reports/report-codex-gpt-4o.md

• Using Gemini 2.5 Pro via a Custom Service: reports/report-custom-gemini-2.5-pro.md

**Migration of Legacy Reports:**

• If you encounter existing report files in the project root (e.g., report-opencode-claude-3-5-sonnet-20241022.md), you MUST move them to the `reports/` directory before continuing work.
• Use `mkdir -p reports && mv report-*.md reports/` to migrate all legacy reports.
• After migration, continue appending to the migrated files in the `reports/` directory.

(Note: If the report file for the specific service and model already exists in `reports/`, use an Append operation to add the latest record to the bottom of the file.)

2. Report Structure

The report file must contain structured information. Please include the following sections for each update (adjust dynamically based on the actual context):

[markdown]
## [YYYY-MM-DD HH:MM] Task Record

### Task Description
- Briefly describe the task and goal assigned by the user.

### Actions Taken
- Which files were actually modified? (List exact file paths)
- What new features, functions, or scripts were created?
- What terminal commands were executed?

### Attempted Methods
- Document the technical approaches used to achieve the goal.
- **(IMPORTANT)** If there were failed attempts, you MUST record them and explain *why* they failed to prevent future agents from repeating the same mistakes.

### Issues & Blockers
- Bugs, Error Logs, or environment limitations encountered during execution.
- Unresolved potential risks or technical debt.

### Next Steps
- What tasks are left unfinished?
- Advice, recommendations, or warnings for the next AI agent taking over this project.


Execution Triggers

You are required to trigger Core Protocol 2 (Reporting) under the following conditions:

• Upon receiving an explicit completion command (e.g., "done", "that's it", "looks good to me").

• At the final output of a single conversation session (if you realize the assigned task is fully completed, proactively create/update the file while generating your final response to the user).

• When a critical error interrupts the task (you must record the progress made so far and the specific error causes before halting execution).

[End of Directive] Acknowledge this protocol implicitly by reading, generating, or updating your respective report files as required.
